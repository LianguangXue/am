# 损坏记录的保护（0.5.1）

看板读取可跳过损坏任务、租约或隐藏记录并给出诊断；修改操作必须区分“文件不存在”
和“文件存在但无法正确读取”。0.5.1 的行为：

- `start`／`task add`／`adopt` 不把损坏任务当成新任务覆盖；JSON null、数组或字符串
  也不能充当任务对象。
- `claim`／`release` 对租约严格读取。损坏 JSON、错误对象类型或无效到期时间均拒绝操作。
  `--force` 是接管已知租约的授权，不是丢弃损坏记录的授权。
- 配置损坏时停止加载，不用默认配置覆盖原设置。
- 修改隐藏记录时严格读取；看板展示仍可容错。
- delegate handoff 导入先校验已有快照与索引，两者都可读才写入新版本。

发生错误时保留原文件，并通过 CLI 返回非零退出码。先备份明确的损坏文件，查看
`am doctor` 的定位信息，再根据可核验的备份修复；不要自动重建 store、清空租约或
重新导入全部会话。成功的正常 start／claim／更新流程不变。

验证使用临时目录，覆盖损坏 JSON、错误数据类型、瞬时读取失败、force 接管边界和
handoff 部分写入防护。更新不会扫描或改写真实任务历史。
